# RAG 只解釋判定，不參與判定

所有判定都只來自規則表與 DRIs 上限計算，由確定性程式產生。RAG 只在報告層使用：它在系統內建、事先 ingest 好的語料（DRIs、NIH ODS、TFDA 仿單）裡，替已經存在的判定找原文佐證，交給 LLM 白話化，並且每句附上引用。RAG 不能新增、刪除或改變任何判定；執行期也不呼叫任何外部資料庫。

這延續了舊專案 legacy ADR-0006 的理由：如果每次評估都去檢索文獻並自動整合證據，同一個人評估兩次可能得到不同結論，也沒有一張固定的表可以檢查。另一方面，它放寬了 legacy ADR-0001「LLM 只能套固定說明」的限制，讓報告可以引用原文。

## Consequences

- 規則表由開發者一人建立。規則可以先由 LLM 協助草擬，但只有人能把規則標成審定。每條規則的出處引文必須逐字出現在 `knowledge/` 的語料中，並由測試自動檢查。這取代了舊專案的雙人覆核，也讓規則和 RAG 共用同一套證據。
- 規則出處只採 TFDA 仿單、NIH ODS HealthProfessional 版、NCCIH fact sheet；NIH ODS Consumer 版只供 RAG 寫白話解釋，不能單獨成立規則；DRIs 只當數值錨。錯開服用的時數必須出自規則引用的原文。
- 這一版不做嚴重度分級，報告中也不出現任何跟嚴重度有關的資訊。
- 報告裡的數值（攝取量、建議總攝取量、上限、上限百分比、錯開時數）由模板直接從判定渲染。LLM 寫的解釋文字不得包含任何數字，由輸出檢查以程式驗證；不合格就重試，仍不合格就改用固定模板。
- 不輸出建議劑量、不建議停用或購買特定產品。建議行動只有三種封閉選項：錯開服用、告知醫師或藥師、併用前先討論。
